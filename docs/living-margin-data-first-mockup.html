v0 — gather word data, derive marks

Marks and cards come from existing datasets (MACULA / OSHB / reverse interlinears / Strong’s maps). No pastor-facing “force” or “consequence” prose required to ship.

  • Token + lemma + morph code — expand codes to English labels via a fixed table
  • Lexicon gloss range — dictionary, labeled as non-contextual
  • Counts — lemma in chapter / book / corpus; form frequency
  • Local concordance — every occurrence + morph form in the book
  • Alignment spans — which English words cover this token per version
  • Divergence mark — when ≥N translations use different content words for the same token
  • Repeat mark — same lemma within N verses (or same chapter)
  • Rarity mark — lemma below a frequency threshold in the corpus
  • Neighborhood — ±k Greek tokens (or syntax parent/children if treebank present)
  • Strong’s / Gk number — searchable alias only

Later — needs judgment or AI

Keep out of v0. These are valuable, but they are products on top of the data layer, not the data layer.

  • Force / consequence / limits — contextual linguistic judgment
  • “Changes the reading” — pastoral significance ranking
  • Sermon-safe rewrite · challenge insight — agent behaviors
  • Commentary agreement map — assertion extraction + verification
  • Root-as-meaning warnings — editorial rules / fallacy library
  • Which genitive sense — ambiguity resolution
  • Argument / narrative / poetic geometry views — need discourse structure beyond morph
